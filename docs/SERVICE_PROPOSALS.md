# Free source-grounded service proposals

Research now has a deterministic fallback for relevant service ideas, without a paid AI key. It uses only the pages refreshed in the latest crawl. It preserves the exact quote and source URL, proposes a change to explore, ranks a small set of service ideas and leaves every idea marked **review required**. It does not qualify a business, create a draft, approve a recipient or send a message by itself.

| Explicit public signal | Proposed offer | What remains unknown |
|---|---|---|
| Campaign A: announced new service | Focused service-page / website build | Whether a separate page is needed, buyer priorities and current plans |
| Campaign A: booking, quote or contact invitation | Website inquiry-journey improvement | Actual conversion friction and private performance metrics |
| Customer questions / published support content | Narrow approved-content chatbot with human handoff | Actual question volume, content suitability and integration needs |
| Campaign B: upcoming store / product range | Store-launch journey | Current checkout plans, products, terms and buyer readiness |
| Campaign B: add-to-cart / buy / shop / order invitation | Product-to-purchase improvement | Whether checkout works and what customers actually experience |
| Campaign B: WhatsApp signup invitation | Permission-based marketing pilot to qualify | Valid customer permission, eligible messages and incremental outcomes |
| Campaign B: public WhatsApp channel | One support/order-update automation to qualify | Channel fit, consent, message requirements and event integration |
| Captured profile, no website found, service/order signal | Campaign A website launch / Campaign B store launch | Search limitations and whether another website exists |

The displayed first proposal follows a fixed cue priority, not a learned prediction of client value or sales likelihood. Up to three service ideas may be stored; the operator chooses one primary offer. Already-captured content that lacks positive signals keeps the earlier needs-review placeholder. Negative statements are not treated as available routes. These rules do not replace semantic review, independent business identity, country/buyer/source ownership, or WhatsApp channel qualification.

Blocked/ambiguous/failed website lookup cannot create a profile-only launch proposal. The pitch still says a website was not found in the search, rather than declaring that none exists. Company-domain contacts, other-domain/profile inbox ownership, verification, four-message review and send gates remain unchanged.

Verification includes direct campaign/quote/ranking/negative/unknown/profile tests, an integrated no-AI crawl-to-proposal check with no qualification/drafts, all existing profile/current-source regressions and the full suite. A read-only check of the current real workspace's thirty saved website pages produced store-improvement and support-chatbot proposals with matching source quotes; the blocked profile had no evidence/proposals. No new recipient probe, external message, qualification or persisted real finding was created by that preview.
