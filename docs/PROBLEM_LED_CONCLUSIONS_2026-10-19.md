# From research to a problem-led email

Raw saved pages establish business context. They do not establish a defective
website, lost enquiries, a missing chatbot or a client's private requirement.

The new conclusion layer maps current, scoped diagnostic observations into:

1. The measured fact, source URL, report reference and capture time.
2. A matching proposed fix or targeted diagnostic next step.
3. Reproduction and before/after verification instructions.
4. Explicit limits on root-cause and business-impact claims.

Website/store improvement drafting now requires a current reproducible finding.
An exploratory business quote alone is insufficient. The real writer stops before
calling the model when no finding exists. Automatic preparation records
`needs_evidence` before qualifying that unsupported offer. Existing edited emails
are preserved. Other positive-evidence offers (for example a sourced new-service
announcement) remain distinct from technical problem claims.

The focused prospect workspace displays the conclusion directly and exposes audit
buttons when the improvement pitch is held. The writer receives the same conclusion;
proof previews contain the finding, proposed fix and verification steps. Generated
copy must cite an available diagnostic reference, retain its measurement and
lab/capture qualifier, and propose a relevant next step. This is bounded validation,
not a guarantee of a model's semantic correctness or a meeting booking.

Using the ordinary public website, Book a Quote advanced to the domestic-property
question. Choosing No advanced to the name field. No contact information was entered
and no enquiry was submitted. This limited check did not reproduce a blocked quote
entry flow. Later steps, delivery and real customer completion remain untested.

The VPS has no PageSpeed API key configured. Its latest saved PageSpeed request
failed with HTTP 429, and both diagnostic reports are stale for the current research.
There are zero current validated observations. Therefore the supported conclusion
is **hold the website-improvement problem pitch**, not invent a website defect.
The existing email is an exploratory offer and is preserved as such.

Current automated diagnostics support scoped Lighthouse lab measurements and clean
capture overflow observations. They do not automatically test every interactive
quote, purchase or chatbot path, infer conversion loss, or establish private client
requirements. A screenshot without a validated observation is not vision analysis.

The optional LCP investigation target uses Google's documented
[LCP guidance](https://web.dev/articles/lcp). A single emulated lab run is not a
field Core Web Vitals assessment or proof that the business loses enquiries.
